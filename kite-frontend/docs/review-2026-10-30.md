# Frontend review — 2026-10-30

Scope: changes since `f815a50`, covering account appbars, public-session SSR,
login redirect, the GSAP demonstration, shared console presentation, policy copy
and footer credit. Review used the existing isolated frontend worktree. No push,
live account/VM mutation, browser automation or Kubernetes command was performed.

## Findings

**Fixed:** `scripts/audit-metadata.mjs` assumed `/login` must always return 200.
Its HTTP run failed with `307 !== 200` after the authenticated-home redirect was
added. The audit now verifies the exact `/` redirect for an authenticated login
request and continues to check the login metadata when anonymous. Both debug and
production HTTP runs pass. Authentication behavior was exercised separately with
the production standalone server and synthetic session API responses.

No further blocking regression was identified within the reviewed code and
HTTP/contract coverage. This is not a visual-QA verdict or a production-operations
approval; the boundaries below remain explicit.

`audit:session` uses ephemeral ports and task-owned servers. It is reproducible
after `npm run build:prod`; it uses real Next SSR and a local HTTP fixture for Go
response contracts. It does not prove that a deployed Go controller or cluster
creates, starts or deletes VMs. The page animation remains an inert local story;
its callbacks do not submit forms, dispatch real clicks, open sockets or mutate
real resources. Source review checked overlay scoping, disabled prefetch, preview
account behavior, motion/visibility cleanup and provider ownership.

## Remaining boundaries

- User-owned visual/interaction QA: cursor target placement, focus/zoom timing,
  modal/menu padding, mobile layout, sidebar transition, profile popup keyboard
  behavior, offscreen pause and OS reduced motion. No Playwright/browser E2E ran.
- Live Go/cluster integration and actual console sockets were not exercised.
- Google OAuth is absent from the current implementation. The privacy wording
  defines the requested processing boundary; it does not add working Google login.
- The deployment's legal operator/contact, concrete log/backup retention and any
  applicable cross-border transfer details still require actual operational facts.
  See `privacy-data-audit.md`; none were invented in this review.

## Structure review

Account usage parsing owns an HTTP boundary; popup presentation owns loading,
error/retry and cleanup. Demo story, GSAP motion, scrolling and camera are separate
small modules and reuse existing form/table/console primitives. Policy pages own
document content rather than authentication or infrastructure implementation.
No new shared account cache, browser auth storage, backend API or persistence
layer was introduced.
